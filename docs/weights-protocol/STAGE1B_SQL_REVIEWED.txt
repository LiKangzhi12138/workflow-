# 2. 当前数据库兼容性

1. 当前 docker-compose.yml 声明 mysql:8.4。
2. model_definition 不与现有表名或 Java Entity 映射冲突。现有主表采用单数 snake_case，例如 workflow、model_asset、dataset_asset。
3. id 为 BIGINT NOT NULL AUTO_INCREMENT，与 workflow、model_asset、dataset_asset、standalone_validation、sys_user 等主表一致；Java 使用 Long 和 IdType.AUTO。
4. 表引擎 InnoDB、字符集 utf8mb4、排序规则 utf8mb4_0900_ai_ci，与当前主要业务表一致。
5. MySQL 8.4 原生支持 JSON、JSON_ARRAY 和 CAST(... AS JSON)。definition_json 与 class_order_json 使用 JSON 类型合理。
6. created_at、updated_at 使用 DATETIME、CURRENT_TIMESTAMP 和 ON UPDATE CURRENT_TIMESTAMP，与现有主表风格一致。
7. Java ModelDefinition 的 Long、Integer、String、LocalDateTime 字段与 SQL BIGINT、INT、JSON/VARCHAR/CHAR、DATETIME 可映射；ModelDefinitionMapper 使用 BaseMapper<ModelDefinition>，表名为 model_definition。
8. Java Workflow.modelDefinitionId 为 Long，与 workflow.model_definition_id BIGINT NULL 一致。
9. 当前静态 SQL 没有发现 idx_workflow_model_definition_id 或同列现有索引，新增索引不与仓库 schema 重复。
10. 执行时使用的数据库应保持 MySQL 默认字符串转义语义，即 @@sql_mode 不包含 NO_BACKSLASH_ESCAPES。当前 seed 使用双反斜杠保证 JSON 最终收到 Unicode 转义。

VARCHAR 长度审核：

- code VARCHAR(64)：足够，当前值 YOLOV8N_SHEEP_V1。
- display_name VARCHAR(128)：足够，当前值 YOLOv8n 羊群检测。
- model_family、model_version、variant、task_type、framework、framework_version、definition_type 均为 VARCHAR(64)：对当前值和合理后续扩展足够。
- definition_version VARCHAR(32)：足够。

- status VARCHAR(32)：足够支持 ENABLED、DISABLED。
- architecture_signature CHAR(64) 与 definition_sha256 CHAR(64)：适合固定长度 SHA-256 十六进制字符串。

# 4. model_definition 表审核

表名与当前命名体系一致，无冲突。

code 具有 uk_model_definition_code 唯一约束。id 为 BIGINT AUTO_INCREMENT。definition_json 和 class_order_json 均为原生 JSON。两个 SHA 字段均为 CHAR(64)。runtime_profile_id 为 VARCHAR(64)。

status 默认 DISABLED 是安全默认值；seed 明确写入 ENABLED。表内索引覆盖 status、runtime_profile_id 和 model_family + variant。

CREATE TABLE IF NOT EXISTS 可安全重复执行，但如果实时数据库已经存在同名且结构不兼容的表，它只会跳过，不会修复结构。因此执行前必须 SHOW CREATE TABLE model_definition；如果表不存在则符合预期。

# 5. workflow.model_definition_id 审核

动态 DDL 只在 information_schema 中确认该列不存在时执行：

ALTER TABLE workflow ADD COLUMN model_definition_id bigint NULL AFTER client_model_asset_id

结论：

- 类型严格为 BIGINT。
- 明确允许 NULL。
- 没有默认 Definition。
- 不影响已有行；历史行保持 NULL。
- 不删除或修改 yolo_version、model_type、task_type 等旧字段。
- 不增加外键。
- Java Entity 已新增 modelDefinitionId，因此运行更新后的 Java 前必须先执行本 SQL。

列存在性判断只按列名判断。如果实时数据库已有同名但错误类型的列，脚本会跳过；执行前应通过 SHOW COLUMNS 核对。

# 7. 幂等性审核

在当前预期 schema 下，整个文件可以重复执行：

1. CREATE TABLE IF NOT EXISTS 不重复创建表。
2. workflow 列通过 information_schema 检查，不重复 ADD COLUMN。
3. workflow 索引通过索引名检查，不重复 CREATE INDEX。
4. Seed 使用 INSERT ... SELECT ... WHERE NOT EXISTS，并由 code 唯一约束兜底，不会生成重复记录。
5. SET、PREPARE、EXECUTE 和 DEALLOCATE 可以再次执行。

没有只能执行一次的语句。

边界说明：

- Seed 是“防重复插入”，不是 upsert。若同 code 已存在但内容不同，重复执行会保留已有行，不会自动覆盖。执行后必须用第 11 节 SELECT 核验。
- 列检查只看列名，索引检查只看索引名。若实时数据库存在同名但结构错误对象，脚本不会修复。
- MySQL DDL 会隐式提交。若中途因权限或连接问题中断，可在排除原因后重跑；脚本会继续补齐缺失步骤。
